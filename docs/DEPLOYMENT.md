# 1. Развёртывание портала на чистом Linux

Целевая система — Astra Linux Special Edition 1.8 с Apache, PHP 8.2 и MariaDB. Портал устанавливается напрямую на ВМ. Для команд нужны административные права. Для другого Linux сопоставьте названия пакетов и конфигурацию веб-сервера.

## Что понадобится и куда идут запросы

| Источник | Когда нужен | Что подготовить для закрытой ВМ |
| --- | --- | --- |
| Ваш сервер Git | Получение конкретной версии проекта | Внутренний Git или файл `git bundle` |
| Репозиторий пакетов Astra, его зеркало или установочный носитель | Обновление ОС и установка Git, Apache, PHP, MariaDB и их зависимостей | Разрешённое внутреннее зеркало либо носитель с пакетами, их зависимостями и подписанными метаданными |
| `codeload.github.com` | Загрузка закреплённого архива InstantCMS, если локальная копия отсутствует | Тот же архив на внутреннем хранилище или носителе. Скрипт умеет читать его с диска |
| Домены InstantCMS | Штатные функции CMS, например RSS на главной админки, каталог дополнений и проверки обновлений | Эти функции не требуются для установки и работы портала. Автоматическая проверка обновлений выключается установщиком компонента |

Git хранит код портала, схему БД, инструкции, сценарии установки и логический бэкап начального наполнения с вложениями. Архив ядра, системные пакеты и данные работающего сайта хранятся отдельно. Для развёртывания без внешних запросов подготовьте эти зависимости заранее. Установка из проверенного локального архива, вход, редактор, новости, документы, тесты и статистика не зависят от сайта CMS. При открытии штатной главной админки браузер автоматически запрашивает у неё RSS, а сервер CMS может обратиться к `api.instantcms.ru`. Вкладка документации в этом блоке обращается к `docs.instantcms.ru`, каталог дополнений тоже использует внешнее API. На закрытой ВМ входите через `/auth/login` и открывайте компонент «Портал ИБ» напрямую по адресу `/admin/controllers/edit/ibportal`. Сетевой запрет исходящих обращений настраивается отдельно средствами вашей сети.

Внутри сети сохраняются обычные зависимости инфраструктуры: разрешение имени портала, синхронизация времени и доверие браузеров к внутреннему сертификату, если используется HTTPS. Вставленные редактором внешние ссылки открываются по нажатию. Изображения памятки и криптошлюза загружайте в портал.

## 1. Подготовить ОС и установить пакеты

Проверьте точную сборку ОС и архитектуру. Выберите разрешённые источники для неё. Для ВМ без интернета подключите внутреннее зеркало или носитель; в нём должны быть и основные пакеты, и их зависимости. Используйте штатную проверку подписей APT.

```sh
cat /etc/os-release
dpkg --print-architecture
sudo apt update
apt list --upgradable
```

Обновите Astra штатной утилитой, предусмотренной для вашей сборки 1.8.x. В примерах `UPDATE_SOURCE` — путь к согласованному ISO обновления. Если используется сетевой репозиторий, подставьте разрешённый адрес из инструкции для этого обновления.

```sh
UPDATE_SOURCE=/mnt/approved/astra-update.iso

# Для сборок, в которых используется astra-update.
sudo astra-update -c "$UPDATE_SOURCE"
sudo astra-update -a "$UPDATE_SOURCE"

# Для сборок, в которых предусмотрен astra-update-modern.
sudo astra-update-modern "$UPDATE_SOURCE" -A
```

Выполните только ветку для своей сборки. Для обновления через графическую оболочку воспользуйтесь «Установка обновлений». После применения обновления перезагрузите ВМ, если этого требует обновление, и снова выполните `sudo apt update`. [Репозитории Astra](https://docs.astralinux.ru/latest/guide/compound/repo/add_install/), [обновление Astra 1.8.3](https://wiki.astralinux.ru/download/attachments/371802537/1.8.3_Ruk_admin_1.pdf?api=v2&modificationDate=1755515725085&version=2), [обновление Astra 1.8.4](https://wiki.astralinux.ru/download/attachments/418185219/1.8.4_Ruk_admin_1.pdf?api=v2&modificationDate=1764138756600&version=1).

```sh
apt-cache policy apache2 php8.2-cli mariadb-server
sudo apt install git ca-certificates curl apache2 mariadb-server mariadb-client \
  php8.2-cli libapache2-mod-php8.2 php8.2-mysql php8.2-mbstring \
  php8.2-xml php8.2-gd php8.2-zip php8.2-curl
sudo a2enmod rewrite headers
sudo systemctl enable --now mariadb apache2
php -v
php -m
sudo apache2ctl -M
```

Ожидается PHP 8.2. В списках проверьте `dom`, `SimpleXML`, `mbstring`, `gd`, `fileinfo`, `mysqli`, `pdo_mysql`, `zip` и модули Apache `php_module`, `rewrite_module`. Если пакет недоступен, проверьте подключённые репозитории и архитектуру. [PHP в Astra](https://docs.astralinux.ru/latest/start/php/), [Apache в Astra](https://docs.astralinux.ru/latest/web_srv/apache2/).

## 2. Получить код портала

Запишите согласованный адрес Git и идентификатор коммита релиза. В примерах замените значения для своего контура и выполните команды в одной оболочке.

```sh
REPO=/srv/ib-portal-src
WEBROOT=/var/www/ib-portal
PORTAL_HOST=ib-portal.example.internal
GIT_URL='https://github.com/beerforator/ib-portal.git'
EXPECTED_COMMIT='ВСТАВЬТЕ_ПОЛНЫЙ_ID_СОГЛАСОВАННОГО_КОММИТА'

sudo install -d -o "$(id -un)" -g "$(id -gn)" -m 0755 "$REPO"
git clone "$GIT_URL" "$REPO"
git -C "$REPO" checkout --detach "$EXPECTED_COMMIT"
git -C "$REPO" rev-parse HEAD
test "$(git -C "$REPO" rev-parse HEAD)" = "$EXPECTED_COMMIT"
git -C "$REPO" status --short
```

`git status --short` должен показать пустой вывод. Если вместо сетевого Git используете `git bundle`, передайте `git clone` путь к файлу и так же сравните коммит. Полный ID сравнивайте с опубликованным владельцем проекта значением, полученным по доверенному каналу. Скрипты ниже запускайте из сохранённого checkout.

## 3. Получить и проверить ядро InstantCMS

Используется GitHub-архив исходников InstantCMS **2.18.2**, тег `2.18.2`, коммит `4a13609c480cccfcbd27dbab424d6bf00ad67375`. Ниже SHA-256 именно этого `tar.gz`. ZIP с сайта InstantCMS имеет другую контрольную сумму. [Репозиторий релиза](https://github.com/instantsoft/icms2/tree/2.18.2), [страница официального релиза](https://instantcms.ru/get/2.18.2).

```text
06afc678c757f34a2070204a06ea321c1ff0849b043590ccd02fb933a4bb77be
```

Для сети с разрешённым доступом к GitHub скачайте архив из следующего адреса. Для закрытой ВМ выполните скачивание на машине подготовки и передайте тот же файл согласованным способом. В текущем Docker есть уже проверенная копия в `/project/cache/instantcms-2.18.2.tar.gz` внутри контейнера `ib-portal-web-1`.

```sh
CORE_ARCHIVE="$PWD/instantcms-2.18.2.tar.gz"
CORE_SHA256=06afc678c757f34a2070204a06ea321c1ff0849b043590ccd02fb933a4bb77be
CORE_URL=https://codeload.github.com/instantsoft/icms2/tar.gz/4a13609c480cccfcbd27dbab424d6bf00ad67375

# Для варианта со скачиванием. Если файл уже перенесён, укажите его путь в CORE_ARCHIVE.
curl -fL --retry 3 -o "$CORE_ARCHIVE" "$CORE_URL"
```

На целевой ВМ укажите полный путь к полученному файлу, выполните сравнение и только при результате `OK` распакуйте ядро.

```sh
printf '%s  %s\n' "$CORE_SHA256" "$CORE_ARCHIVE" | sha256sum -c -
sudo sh "$REPO/bin/bootstrap-core.sh" "$WEBROOT" "$CORE_ARCHIVE"
```

При несовпадении остановитесь и получите архив заново из указанного источника. Скрипт повторно проверит SHA-256 и распакует архив в пустой веб-каталог. Со вторым аргументом он не обращается в сеть.

## 4. Создать базу и подготовить права

Создайте пароль БД в менеджере паролей. В примере замените маркер своим значением. Для SQL-строки можно использовать случайный пароль из шестнадцатеричных символов. Пароли БД и первого администратора задаются отдельно.

```sh
sudo mariadb
```

```sql
CREATE DATABASE ib_portal CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
CREATE USER 'ib_portal'@'localhost' IDENTIFIED BY 'ЗАМЕНИТЕ_НА_ПАРОЛЬ_БД';
GRANT ALL PRIVILEGES ON ib_portal.* TO 'ib_portal'@'localhost';
EXIT;
```

```sh
mariadb --host=localhost --user=ib_portal --password ib_portal -e 'SELECT DATABASE();'

sudo install -d -o www-data -g www-data -m 0750 /var/lib/ib-portal
sudo install -d -o www-data -g www-data -m 0700 /var/lib/ib-portal/.sessions
sudo chown -R www-data:www-data "$WEBROOT/cache" "$WEBROOT/upload" "$WEBROOT/system/config"
```

Файлы самого приложения принадлежат администратору системы. Право записи веб-серверу нужно только для перечисленных каталогов. Документы и изображения портала будут в `/var/lib/ib-portal`, за пределами веб-каталога.

## 5. Настроить Apache, адрес и PHP

Подготовьте DNS-запись или предусмотренное в сети разрешение имени `PORTAL_HOST`. Убедитесь, что рабочие места открывают именно этот хост. Для рабочего портала используйте HTTPS с сертификатом внутреннего центра сертификации. Настройте его до запуска мастера, чтобы мастер сохранил окончательные URL. Если TLS завершает внутренний обратный прокси, используйте настройки вашего прокси и официального имени.

```sh
sudo install -m 0644 "$REPO/deploy/apache-vhost.conf" /etc/apache2/sites-available/ib-portal.conf
sudoedit /etc/apache2/sites-available/ib-portal.conf

printf '%s\n' 'upload_max_filesize=32M' 'post_max_size=36M' |
  sudo tee /etc/php/8.2/apache2/conf.d/99-ib-portal.ini >/dev/null

sudo a2ensite ib-portal
sudo apache2ctl configtest
sudo systemctl reload apache2
```

В конфигурации замените `ServerName`. Для локального TLS на Apache используйте `sudo a2enmod ssl` и перенесите пример виртуального хоста на `<VirtualHost *:443>`, сохранив секции `Directory`. Внутри добавьте реальные пути к сертификату с цепочкой и закрытому ключу.

```apache
SSLEngine on
SSLCertificateFile /etc/ssl/certs/ib-portal-fullchain.pem
SSLCertificateKeyFile /etc/ssl/private/ib-portal.key
```

Проверьте конфигурацию и перезагрузите Apache после изменения. Откройте доступ с администраторского рабочего места для установки. Доступ к порту MariaDB с рабочих мест порталу не требуется. Если браузер не доверяет сертификату, проверьте цепочку и доверие к внутреннему УЦ.

## 6. Пройти мастер InstantCMS

Откройте `https://ВАШ_ХОСТ/install/` с рабочего места администратора. Для отдельной установки с HTTP используйте её собственный адрес и схему. На странице мастера разметка и локальные ресурсы по-прежнему доступны, даже если браузер или журнал видит HTTP 503 до окончания установки.

1. Выберите **Русский**, примите лицензию и пройдите проверку PHP.
2. Оставьте корень `/`, загрузки `/upload/`, кэш `/cache/`. Для сессий укажите `/var/lib/ib-portal/.sessions`. URL сайта должен совпадать с фактическим адресом, например `https://ib-portal.example.internal`. Для загрузок используйте его же с `/upload`.
3. Задайте имя сайта. Шаблон сайта — `modern`, шаблон админки — `admincoreui`. Отключите проверку обновлений.
4. Введите `localhost`, БД и пользователя `ib_portal`, пароль БД из шага 4. Префикс `cms_`, кодировка `utf8mb4`, движок `InnoDB`. Выберите создание таблицы пользователей и снимите флажок установки демоданных CMS.
5. Укажите имя, рабочую почту и новый пароль первого администратора. Сохраните его в менеджере паролей. Завершите мастер. Для входа на рабочей ВМ пригодятся именно эти реквизиты.

## 7. Установить компонент портала

Когда мастер закончит работу, проверьте наличие `system/config/config.php` и перенесите установщик из веб-каталога. Сценарий создаёт таблицы портала и включает его в качестве главной страницы.

```sh
sudo test -f "$WEBROOT/system/config/config.php"
sudo mv "$WEBROOT/install" /var/lib/ib-portal/.installer
sudo chown www-data:www-data "$WEBROOT/system/config/config.php"
sudo chmod 0600 "$WEBROOT/system/config/config.php"
sudo php "$REPO/bin/install-portal.php" "$WEBROOT"
```

Чтобы заполнить чистый портал готовыми материалами из Git, выполните:

```sh
sudo -u www-data php "$REPO/bin/restore-content.php" "$WEBROOT"
```

Скрипт импортирует настройки заголовков и меню, футер, памятку и текст страницы криптошлюза. Также появятся две новости, два раздела документов, четыре файла и один тест. Все вложения копируются в `/var/lib/ib-portal` после проверки SHA-256. Первый администратор и остальные учётные записи остаются такими, как их создал установщик. История просмотров и результаты тестов в резервную копию наполнения не входят. Импорт откажется работать, если в портале уже есть материалы или сохранённые настройки оформления.

Источник импорта — `database/initial-content/content.json`, логическая копия таблиц содержимого. Сам архив InstantCMS по-прежнему загружается или передаётся отдельно. Если нужно начать с пустого портала, пропустите импорт. На отдельном пустом тестовом стенде вместо импорта можно запустить `sudo -u www-data php "$REPO/bin/seed-demo.php" "$WEBROOT"`.

## 8. Сравнить развёрнутые файлы и выполнить приёмку

Сравните все файлы компонента в веб-каталоге с файлами из выбранного Git-коммита. Команды выполняются на целевой ВМ. Контрольные суммы вычисляются из `overlay` и проверяются по тем же относительным путям в веб-каталоге.

```sh
MANIFEST=$(mktemp)
(
  cd "$REPO/overlay" &&
  find . -type f -print0 | LC_ALL=C sort -z | xargs -0 -r sha256sum
) > "$MANIFEST"
test -s "$MANIFEST"
(cd "$WEBROOT" && sha256sum -c "$MANIFEST")
rm -f "$MANIFEST"
```

Ожидается `OK` для каждого файла. Если есть `FAILED`, проверьте Git-коммит и локальные правки, затем повторите установку компонента из проверенного checkout. Архив ядра уже проверен в шаге 3. Для отчёта фиксируйте ID коммита портала, SHA-256 архива InstantCMS и результат проверки файлов.

```sh
curl -fSs -o /dev/null -w '%{http_code}\n' "https://$PORTAL_HOST/"
curl -fSs -o /dev/null -w '%{http_code}\n' "https://$PORTAL_HOST/ibportal/crypto"
```

На рабочем месте с отключённым внешним доступом откройте главную и `/auth/login`. Войдите, опубликуйте пробную новость и документ, пройдите тест и проверьте результат. Убедитесь, что при открытии публичной страницы меняется её счётчик и документация редактора соответствует интерфейсу. Для проверки загрузки изображений используйте локальный файл. См. [инструкцию для администратора](ADMIN.md).

## Обновление и резервная копия

Перед обновлением сохраните дамп БД, содержимое `/var/lib/ib-portal`, штатный конфиг InstantCMS и ID установленного коммита. Развёртывайте обновления из согласованного checkout. При обновлении только компонента уже установленного портала повторите `sudo php "$REPO/bin/install-portal.php" "$WEBROOT"`, затем сравните контрольные суммы и проверьте сайт. Обновление ядра CMS — отдельная процедура. План резервного копирования и ограничения специальных режимов Astra сверяйте с настройками своей ВМ.

Последовательность распаковки ядра, установки CMS, установки компонента и работы без внешнего интернета проверена на отдельном Linux-стенде в Docker. Пакеты, службы и политики конкретной ВМ Astra проверяет администратор при приёмке.
